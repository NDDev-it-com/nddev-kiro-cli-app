# NDDev Builder

Use this skill to keep public setup-manager modules aligned with the NDDev boundary: runtime code, setup catalogs, public contracts, release metadata, and user documentation stay in the module; private tests and benchmarks stay outside it.

When building a Kiro setup manager, verify current Kiro docs before naming a native surface. Use Kiro agents, skills, steering, hooks, MCP, and permissions only when the official Kiro CLI documentation supports the format.
